# 测试说明

## 1. 目标

测试工作的目标是保障项目主功能可以稳定落地，而不是追求无边界覆盖。

当前测试只围绕四条主链路展开：

- 药品管理
- 库存管理
- 预警查询
- 处方发药

## 2. 当前测试层次

当前测试分为三层：

### 2.1 单元测试

主要用于验证：

- 参数校验
- 业务规则
- 状态流转
- 异常拒绝逻辑

### 2.2 H2 集成测试

主要用于验证：

- 主流程联动
- Mapper 映射
- 事务链路

当前已经覆盖：

- 处方分页与状态更新 Mapper 测试
- `代开授权 -> 审核 -> 发药 -> 扣库存 -> 写流水` 集成测试

### 2.3 容器化验证

这一层当前还未补齐完整自动化说明，但后续必须补。

目标是验证：

- MySQL 容器初始化成功
- 后端能够连接容器数据库
- 演示环境配置与本地逻辑一致

## 3. 当前已完成测试范围

当前已覆盖的重点包括：

- 药品编码唯一性与逻辑删除
- 库存入库、出库、盘点
- 低库存与效期预警
- 医生直开与药师代开
- 处方审核与发药
- 发药扣库存与流水写入

## 4. 后续补测优先级

为了更快支撑项目落地，后续测试优先补以下内容：

1. 库存不足场景
2. 医生越权审批场景
3. 已发药重复发药场景
4. 发药链路回滚场景
5. 前后端联调后的接口级回归

## 5. 测试执行建议

当前建议按以下顺序执行测试：

1. 单元测试
2. H2 集成测试
3. 容器环境运行验证

## 6. 与 Docker 的关系

测试说明需要明确一件事：

- `H2` 是当前阶段的快速验证工具
- `Docker + MySQL` 是后续演示和交付的真实环境验证工具

两者不是替代关系，而是阶段不同、职责不同。

## 7. 面向落地的验收标准

项目继续推进时，每完成一个主要功能模块，至少满足以下条件：

- 功能接口可调用
- 关键规则有测试
- 主链路不回归
- 文档有更新
- 可加入演示路径
