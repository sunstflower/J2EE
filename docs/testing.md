# 测试说明

## 1. 目标

测试工作的目标是保障项目主功能可以稳定落地，而不是追求无边界覆盖。

当前测试只围绕最小演示闭环展开：

- 库存预览
- 药物入库
- 开药扣库存

## 2. 当前测试层次

当前测试分为三层：

### 2.1 单元测试

主要用于验证：

- 参数校验
- 业务规则
- 状态流转
- 异常拒绝逻辑

### 2.2 H2 集成测试

主要用于验证：

- 主流程联动
- Mapper 映射
- 事务链路

当前已经覆盖：

- 处方分页与状态更新 Mapper 测试
- 药品服务规则测试
- 预警服务测试
- Spring Boot 上下文启动测试

### 2.3 Shell 功能性测试

这一层用于从接口角度验证演示环境主链路。

当前已经补充独立脚本文档：

- `docs/functional-test-shell.md`

目标是验证：

- 健康检查可用
- 医生与药师账号均可登录
- 库存分页与低库存查询可用
- 入库接口成功并带来库存变化
- 医生开药成功
- 药师越权开具处方药时被拒绝

## 3. 当前已完成测试范围

当前已覆盖的重点包括：

- 药品编码唯一性与逻辑删除
- 低库存与效期预警查询
- 处方分页与状态字段映射
- Spring Boot 配置可启动
- Shell 脚本方式的主链路接口验收说明

## 4. 后续补测优先级

为了更快支撑项目落地，后续测试优先补以下内容：

1. 入库记录接口成功与失败场景
2. 医生开药导致库存精确扣减场景
3. 药师固定针对处方药越权场景
4. 库存不足时开药失败场景
5. 前后端联调后的接口级回归

## 5. 测试执行建议

当前建议按以下顺序执行测试：

1. 单元测试
2. H2 集成测试
3. Shell 功能性测试
4. 容器环境运行验证

## 6. 与 Docker 的关系

测试说明需要明确一件事：

- `H2` 是当前阶段的快速验证工具
- `Shell + HTTP 接口` 用于直接验证功能主链路
- `Docker + MySQL` 是演示和交付时的真实环境验证工具

三者不是替代关系，而是阶段不同、职责不同。

## 7. 面向落地的验收标准

项目继续推进时，每完成一个主要功能模块，至少满足以下条件：

- 功能接口可调用
- 关键规则有测试
- 主链路不回归
- 文档有更新
- 可加入演示路径
