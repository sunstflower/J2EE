# 演示脚本

## 1. 目标

本脚本用于指导项目最终演示，只围绕主功能闭环，不展示次要能力。

演示目标：

- 展示系统已经具备完整后端主链路
- 展示药品、库存、预警、处方之间的联动关系
- 为后续前端页面联调提供统一业务顺序

## 2. 演示前准备

演示前至少确认以下内容：

- 数据库已初始化
- 后端服务可访问
- 前端页面可访问
- 演示药品数据存在
- 演示库存数据存在

## 3. 推荐演示顺序

### 3.1 药品管理

展示重点：

- 查询药品列表
- 查看药品详情
- 如需补演示数据，可新增一个药品

目的：

- 说明后续库存和处方都依赖药品主数据

### 3.2 库存管理

展示重点：

- 对某个药品执行入库
- 查询库存列表
- 查看库存详情
- 查询库存流水

目的：

- 说明库存按批次管理
- 说明库存流水可追溯

### 3.3 预警查询

展示重点：

- 查询低库存预警
- 查询临期或过期预警

目的：

- 说明系统能对库存风险做实时提示

### 3.4 处方创建

展示重点：

- 医生直接创建处方
  或
- 药师代医生发起处方

目的：

- 说明系统支持两类开方入口

### 3.5 医生授权

如果演示的是药师代开场景，应展示：

- 医生确认代开
  或
- 医生拒绝代开

目的：

- 说明药师不能绕过医生直接完成处方流转

### 3.6 药师审核

展示重点：

- 审核通过处方
  或
- 驳回处方

目的：

- 说明处方必须经过审核流转

### 3.7 发药与库存扣减

展示重点：

- 对已审核通过处方执行发药
- 再次查询库存列表
- 查询库存流水
- 查询处方详情状态

目的：

- 说明发药会联动扣减库存
- 说明发药后处方状态与库存流水都会更新

## 4. 建议准备的演示数据

为了保证主链路稳定，建议准备：

- 1 个医生身份
- 1 个药师身份
- 2 个药品
- 至少 1 个药品具备 2 个不同效期批次库存
- 至少 1 个低库存药品

## 5. 推荐演示主线

如果只演示一条最核心链路，建议使用：

1. 查询药品
2. 为药品入库
3. 查询库存与流水
4. 创建药师代开处方
5. 医生授权
6. 药师审核
7. 药师发药
8. 查询库存扣减结果与处方最终状态

## 6. 演示时的重点说明

演示过程中建议重点强调：

- 药品是主数据基础
- 库存按批次和效期管理
- 预警基于库存和效期计算
- 处方流转有角色限制
- 发药与库存扣减是同一条主业务链路

## 7. 演示阶段不必重点展开的内容

为了专注主功能，当前演示不必重点展开：

- 复杂权限模型
- 非核心扩展页面
- 额外统计报表
- 非主链路异常分支
