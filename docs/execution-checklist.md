# 项目执行清单

## 1. 目标

本清单用于把现有设计文档收敛成可直接执行的落地步骤。

执行原则：

- 只围绕主功能闭环推进
- 每一步都要有明确产出
- 每一步都要有最低验收标准

## 2. 当前基线

当前已经完成：

- 后端药品模块
- 后端库存模块
- 后端预警模块
- 后端处方模块
- 最小认证基线后端接入
- 前端最小登录入口
- 数据库初始化脚本
- 后端单元测试与 H2 集成测试基线
- 前端基础页面测试基线
- Docker 骨架
- API、测试、演示、认证、联调、部署文档基础说明

当前未完成：

- 前端路由化与导航整改
- 前端公共交互与分页能力整改
- Docker 演示环境业务脚本级验收
- 最终部署交付验证
- 后端基于当前用户上下文进一步收口操作者字段

## 3. 执行总顺序

后续工作按以下顺序执行：

1. 认证基线收口
2. 前端结构整改
3. 前端交互整改
4. Docker 演示验证
5. 部署验证

## 4. 分阶段执行清单

### 阶段一：认证接入

目标：

- 建立当前用户概念
- 区分医生与药师身份
- 为处方授权、审核、发药提供真实操作者上下文

执行项：

- 已完成：
  - 增加当前用户上下文对象
  - 增加请求头解析拦截器
  - 统一解析：
    - `X-User-Id`
    - `X-User-Name`
    - `X-User-Role`
  - 增加 `GET /api/auth/me` 联调接口
  - 增加前端最小登录入口
- 待完成：
  - 后端逐步改造创建人和操作人信息由上下文注入
  - 补充前后端联调验证记录

产出物：

- 认证相关代码
- 对应测试
- 文档更新

验收标准：

- 医生请求可识别为医生
- 药师请求可识别为药师
- 非法角色请求被拒绝
- 前端登录后可稳定切换演示身份
- 处方关键操作不再依赖前端手填操作者字段

参考文档：

- `docs/authentication.md`

### 阶段二：前端结构整改

目标：

- 让前端结构与文档声明保持一致
- 消除单页堆叠工作台带来的演示问题

执行项：

- 登录页
- 路由壳层首页
- 侧边栏或顶部导航
- 药品列表页
- 库存管理页
- 库存流水页
- 预警页
- 处方工作台页

产出物：

- 页面代码
- 基础组件
- 前端测试
- 文档更新

验收标准：

- 页面可访问
- 模块可通过独立路由访问
- 列表可展示
- 表单可提交
- 状态可区分
- 医生和药师看到的关键操作入口不同

当前状态：

- 未完成
- 当前仍为 `HomePage` 纵向堆叠 4 个业务模块的单页工作台
- 后续必须先完成路由化，再继续新增前端功能

参考文档：

- `docs/frontend-integration.md`
- `docs/api.md`

2. 分页控件
3. 页面公共状态管理
4. 角色导航差异

产出物：

- 前端整改代码

验收标准：

- 删除操作无误触直删
- 分页列表具备可见翻页入口
- 页面提示行为一致

参考文档：

- `docs/frontend-integration.md`

## 5. 主功能验收清单

项目落地前，必须逐项确认以下主功能：

- 药品可新增、查询、修改、删除
- 库存可入库、出库、盘点
- 库存流水可查询
- 低库存预警可查询
- 临期/过期预警可查询
- 医生可直接创建处方
- 药师可代开发起处方
- 医生可授权或拒绝代开
- 药师可审核处方
- 药师可发药
- 发药后库存会扣减
- 发药后库存流水会写入

## 6. 前端整改验收清单

- 已引入真实路由，不再使用长滚动工作台承载全部模块
- 导航层可区分医生与药师入口
- 列表页具备分页控件
- 删除操作具备二次确认
- 页面公共请求状态已抽取复用
- 文档中的前端结构与代码实现一致

## 7. 每阶段统一交付要求

每完成一个阶段，至少交付：

- 代码
- 测试
- 文档
- 验证结果

如果缺少其中任意一项，不算阶段完成。

1. 开始处方页面与真实 API 联调
2. 收口主链路联调验证记录
3. 药品、库存、预警、处方页面联调
