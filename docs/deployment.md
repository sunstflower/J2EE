# 部署说明

## 1. 目标

本说明用于约束项目最终落地交付方式，当前只聚焦单机容器化部署，不扩展到复杂集群。

部署目标：

- 项目可在一台机器上启动
- 数据库、后端、前端、Nginx 能协同运行
- 主功能可直接演示

## 2. 当前建议部署方式

当前建议使用：

- `Docker Compose`

原因：

- 与当前仓库结构一致
- 配置简单
- 适合答辩、演示和本地交付

## 3. 当前部署组件

部署最小集合如下：

- `mysql`
- `backend`
- `frontend`
- `nginx`

## 4. 部署前检查项

部署前至少确认：

- Docker 可用
- Docker Compose 可用
- 端口 `3306`、`8080`、`5173`、`80` 未冲突
- `docker/mysql/init` 中脚本顺序正确
- 前后端构建文件存在
- 当前机器可拉取 `mysql`、`maven`、`nginx`、`node` 基础镜像

## 5. 部署后验证项

部署完成后至少验证：

- MySQL 容器正常
- 后端健康接口正常
- 前端页面可访问
- Nginx 能代理前端与 API
- 主功能链路可演示

推荐验证命令：

```bash
docker compose ps
curl http://localhost:3000/api/health
```

## 6. 主功能验收

部署完成后，至少完成一次主链路验证：

1. 查询药品列表
2. 执行库存入库
3. 查询库存与流水
4. 查询预警
5. 创建处方
6. 医生授权
7. 审核处方
8. 发药并确认库存扣减

## 7. 当前部署边界

当前文档阶段不覆盖以下内容：

- 集群部署
- 自动扩缩容
- 灰度发布
- 多环境配置中心

原因是这些内容超出当前项目主功能落地范围。

## 8. 后续需要补的实操内容

为了让部署说明真正可执行，后续还应补齐：

- 日志查看命令
- 常见故障排查

当前最小部署命令：

```bash
docker compose up --build -d
```

当前停止命令：

```bash
docker compose down
```

当前数据重置命令：

```bash
docker compose down -v
```

当前验证备注：

- 本仓库已完成前端生产构建、后端打包、Compose 结构和 Nginx 配置语法校验
- 若要完成最终部署验收，仍需在安装了 Docker 的机器上执行实际 `docker compose up --build -d`
