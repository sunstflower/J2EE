# 前端范围收缩说明

## 1. 目标

当前前端页面过多、入口过杂，不利于现场演示。

本说明用于明确新的前端收口范围：

- 只保留最必要的演示功能
- 降低页面复杂度
- 让角色边界一眼可见

## 2. 收口后的功能

前端只保留以下三项功能：

### 2.1 库存预览

展示内容：

- 当前药品库存
- 批次号
- 有效期
- 数量
- 低库存提醒

要求：

- 低库存预警直接展示在库存预览页
- 不再单独提供独立“预警查询”主入口

### 2.2 开药

展示内容：

- 医生填写患者与药品信息
- 医生提交处方药开具请求

要求：

- 仅医生账号可使用
- 药师账号不得开出处方药

### 2.3 药物入库

展示内容：

- 药品入库表单
- 入库成功反馈
- 入库后库存联动刷新

要求：

- 只保留入库动作
- 暂不把出库、盘点、库存流水作为首页主演示项

## 3. 页面建议

### 3.1 登录后主页

主页建议只显示 3 个入口按钮：

- `库存预览`
- `开药`
- `药物入库`

### 3.2 药师账号主页

药师账号登录后：

- 显示 `库存预览`
- 显示 `药物入库`
- 不显示 `开药`

### 3.3 医生账号主页

医生账号登录后：

- 显示 `库存预览`
- 显示 `开药`
- 可视情况决定是否显示 `药物入库`

如果继续保留入库给医生，也应弱化其优先级。

## 4. 不再作为主展示内容的页面

以下页面或能力不再作为当前首页主展示范围：

- 完整药品 CRUD 页面
- 独立预警查询页面
- 完整库存流水页面
- 完整处方审核工作台
- 医生授权 / 药师审核 / 发药多步骤大工作台

说明：

- 后端可保留这些接口
- 前端主演示页不必继续承载这些完整流程

## 5. 当前实现要求

后续代码整改时，应以本说明为准：

1. 首页做减法，不做加法
2. 模块数严格限制为 3 个
3. 开药能力只给医生
4. 库存预览直接带低库存提示
5. 入库页只负责入库
