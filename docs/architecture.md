# 架构设计说明

## 0. 配套图示

当前项目的 Mermaid 架构图见：

- `docs/architecture-mermaid.md`

## 1. 当前收口目标

当前项目不再追求“把所有已实现模块都放到首页展示”，而是收口为最小可演示版本。

本轮前端收口后，只保留以下三项功能：

- 库存预览
- 开药
- 药物入库

其余能力如完整药品管理、完整预警查询、完整处方流转工作台，后端可以继续保留，但前端首页不再作为主展示范围。

## 2. 前端页面结构

前端建议收敛为以下结构：

### 2.1 主入口

- 登录页
- 登录后进入简化主页

### 2.2 简化主页

主页只展示 3 个主按钮或卡片入口：

1. `库存预览`
2. `开药`
3. `药物入库`

不再把库存、预警、处方、药品等多个模块全部平铺到一个复杂工作台。

## 3. 功能边界

### 3.1 库存预览

库存预览页用于展示当前库存状态，页面重点应包括：

- 药品名称
- 当前库存数量
- 批次号
- 有效期
- 低库存状态

页面目标：

- 让演示者快速看到当前库存中“有什么药”
- 让演示者快速看到“哪些药已经低库存”

说明：

- 低库存预警不再单独做成一个独立主入口
- 低库存信息直接并入库存预览页展示

### 3.2 开药

开药页用于医生开具处方，页面重点应包括：

- 患者姓名
- 药品选择
- 剂量
- 频次
- 天数
- 数量

关键规则：

- 处方药只能由医生账号开出
- 药师账号登录后，不展示“开药”主功能入口，或展示为不可用状态

当前演示目标下，不要求前端继续展示完整的：

- 药师代开申请
- 医生授权流转
- 审核工作台
- 发药工作台

如果后端保留这些能力，可作为后续扩展，不作为当前首页主功能。

### 3.3 药物入库

药物入库页用于维护库存补充，页面重点应包括：

- 药品 ID 或药品选择
- 批次号
- 有效期
- 数量
- 库位
- 业务单号
- 备注

页面目标：

- 支撑最小库存补货演示
- 演示入库后库存预览页的数据联动刷新

## 4. 角色边界

当前前端只保留两类角色：

- 医生
- 药师

角色边界收口如下：

### 4.1 医生

医生登录后可见：

- 库存预览
- 开药
- 药物入库

### 4.2 药师

药师登录后可见：

- 库存预览
- 药物入库

药师不可见或不可操作：

- 开药

说明：

- 如果界面保留“开药”按钮，也必须是禁用态，并明确说明“处方药仅医生可开”
- 更推荐直接在导航层隐藏该入口

## 5. 演示路径

当前推荐演示路径应收敛为：

1. 登录系统
2. 进入库存预览，查看当前库存和低库存提醒
3. 进入药物入库，执行一次入库
4. 返回库存预览，确认库存变化
5. 使用医生账号进入开药页，开出一张处方药

如果只演示最短闭环，建议使用：

1. 药师登录
2. 查看库存预览
3. 执行药物入库
4. 医生登录
5. 执行开药

## 6. 落地原则

为了让页面更清晰，后续实现应遵循：

- 首页只保留 3 个入口，不再堆叠全部业务模块
- 库存预览页要把“库存信息 + 低库存预警”合并展示
- 开药页必须做医生角色限制
- 入库页只做一类动作，不混入出库、盘点、流水等次要演示项
- 所有页面优先服务演示效率，而不是功能罗列完整度
